Open calls for the owner

1. Faction/Treasure GM-secret split — deliberately NOT built. Only npcs.stat_block got the table-split treatment. Faction disposition/goal and treasure location/notes stay fully party-visible in this pass — matching the scoping decision ("Hide stat_block from players now"), not a broader GM/player split across every world table. Flag here if that's wrong and something in Factions/Treasure should also move behind RLS.

2. NPC ordering. npcs has no sort_order column (unlike quests), so listNpcs() sorts by created_at — i.e. import order, which happens to roughly follow the campaign's own chronology above. Worth a real sort key later (e.g. by status, or a manual GM-set order) once NPC count grows past what "introduced-in-order" comfortably represents.

3. Card component split. This mockup shows NpcCard/FactionCard/TreasureRow as one visual family so the three tabs read as one overlay — task #52 builds these as three separate components (NpcCard.tsx, FactionCard.tsx, TreasureRow.tsx), not one shared card, since their real field sets diverge (only NpcCard has a GM-only section; only Treasure is row-shaped rather than card-shaped).
